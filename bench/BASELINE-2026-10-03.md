# Baseline Benchmarks — 2026-10-03 (BENCH lane, _build-map6)

Two runs each of `bench/hot_paths_bench.exs` and `bench/store_scaling.exs`.
Environment: aarch64-apple-darwin25.2.0, OTP 28, Elixir 1.19.5, 16 schedulers.
In-script harnesses only (no Benchee; no deps added).

## Reproduce

```sh
MIX_BUILD_ROOT=_build-map6 MIX_ENV=test mix run bench/hot_paths_bench.exs bench/hot_paths_raw1.json
MIX_BUILD_ROOT=_build-map6 MIX_ENV=test mix run bench/hot_paths_bench.exs bench/hot_paths_raw2.json
MIX_BUILD_ROOT=_build-map6 MIX_ENV=test mix run bench/store_scaling.exs > bench/store_scaling_map6_raw1.txt
MIX_BUILD_ROOT=_build-map6 MIX_ENV=test mix run bench/store_scaling.exs > bench/store_scaling_map6_raw2.txt
```

Raw captures: `bench/hot_paths_raw1.json`, `bench/hot_paths_raw2.json`
(script writes JSON when given an out path), `bench/store_scaling_map6_raw1.txt`,
`bench/store_scaling_map6_raw2.txt` (stdout pipe-table capture; script takes no argv).

**Machine-load caveat**: concurrent compile lanes and other bench lanes were
active on the same host during these runs; high-stddev rows (engine paths,
DETS writes) move substantially between runs and should be read as
order-of-magnitude, not precise. Each script's own batch stddev is reported.

## Reading

- ETS hot paths are stable across runs (±10% except where noted); standing
  receipt and FOND checks are tight (stddev < 5%).
- DETS engine loop and DETS checkpoint writes are 1–2 orders of magnitude
  slower than ETS and high-variance (run-to-run delta up to −42%) —
  consistent with DETS file-position churn under machine load, not a code
  change between runs (same checkout, same build root).
- ETS `checkpoints/2` scan grows super-linearly (69 µs @100 → ~15–17 ms @10k).
- DETS signal dispatch throughput is ~3 orders of magnitude below ETS
  (~30–95 ops/s vs ~100k–195k ops/s).
