## 2. Upstream workflow-pack conventions (read from
`priv/ggen/ash-pplan-workflow-pack/`, mirrored from the upstream
ggen-marketplace pplan packs — note: no `ash-pplan-workflow-pack` exists at
`/Users/sac/ggen-marketplace/packs/` yet; upstream has
`ash-pplan-{chaos,igniter,protocol-court,store-conformance}-pack` only, so
this design's "upstream" is the in-tree pack which becomes the upstream on
publish)

- EEX templates with YAML frontmatter: `to:`, `mode: file`,
  `for_each: <row-class>`; output path may interpolate
  (`<%= provider_id %>.ex`).
- Rows come from SPARQL gates (`gates/*.rq`) over the merged ontology;
  e.g. `020_providers.rq` selects `?provider_id ?module ?cost`.
- Templates are self-contained Elixir-formatters: big `<% ... %>` preamble
  defining `scalar/1`, `normalize/1`, `to_atom/1`, camelization, row
  filtering by foreign key (`workflow == wname`), then the module body.
- Manufacturer wiring: `bin/manufacture-workflow` (generic, lib/) and
  `bin/manufacture-examples` (merges `ontology.ttl` +
  `test/support/examples/ontology/examples.ttl` into
  `tmp/examples-ontology.ttl`, MIX_ENV=test, syncs per-template with
  `--for-each`, `--on-stale prune`).
- Gate+verify pattern: each recipe has a `gates/<n>_<x>.rq` that must
  return non-zero rows and a `verify/*_unbound.rq` that must return zero
  unbound vars.
- Court pattern: `test/courts/igniter_gen_byte_identity_court_test.exs`
  — determinism (two renders byte-identical), diff-stability (render vs
  committed file under `Code.format_string!/1` normalization),
  anti-vacuity (mutate one ontology fact, render must diverge), plus
  gates-nonempty probe.

## 3. Design: AshResource row family + templates

### 3.1 New row classes (in `examples.ttl`, ex: namespace; SHACL shapes in
`ontology/shapes.ttl`)

```
ap:ExampleDomain   a rdfs:Class       # one per domain module
ap:ExampleResource a rdfs:Class       # one per Ash resource
  ap:resourceId     "order"           # slug -> module suffix
  ap:domain         ex:dom_qf
  ap:dataLayer      "ets"             # ets | ets_private | postgres
  ap:primaryKey     "uuid"
  ap:attributes (list of ap:ExampleAttribute)
ap:ExampleAttribute
  ap:attrName "status"; ap:attrType "atom";
  ap:attrConstraints "one_of: [:new,:admitted,:verified,:fulfilled]";
  ap:attrDefault ":new"; ap:attrPublic true; ap:attrAllowNil false
ap:ExampleAction
  ap:actionName "admit"; ap:actionKind "update";
  ap:actionAccept ""; ap:actionValidate "attribute_equals(:status,:new)";
  ap:actionChange "set_attribute(:status,:admitted)";
  ap:actionAtomic false; ap:actionCompensates "unadmit"
```

Domain rows:

```turtle
ex:dom_qf a ap:ExampleDomain ;
    ap:domainModule
      "AshPPlan.Examples.QualifiedFulfillment.Domain" ;
    ap:authorizations "reading: *, commands: *" .

ex:res_order a ap:ExampleResource ;
    ap:resourceId "order" ;
    ap:domain ex:dom_qf ;
    ap:dataLayer "ets" ;
    ap:attribute [ a ap:ExampleAttribute ;
        ap:attrName "sku" ; ap:attrType "string" ;
        ap:attrAllowNil false ; ap:attrPublic true ] ,
      [ ... status with one_of constraint + default :new ] ;
    ap:action [ a ap:ExampleAction ;
        ap:actionName "admit" ; ap:actionKind "update" ;
        ap:actionValidate "attribute_equals(:status, :new)" ;
        ap:actionChange "set_attribute(:status, :admitted)" ;
        ap:actionAtomic false ] .
```

The three integration resources become three more `ap:ExampleResource`
rows with `ap:resourceId "control_plane_integration"` etc., parameterized
by `ap:extension "ash_control_plane" | "ash_oban" | "ash_state_machine"`
plus `ap:extensionBlock` (the verbatim `extensions do ... end` body, one
quoted string per row — the only free-text slot; everything else is
structured).

### 3.2 Parameterization: provider ids -> @table bindings

Same mechanism the provider template already uses: rows selected by gate,
template filters child rows by foreign key. For resources the binding
table is:

```
@table in generated resources: NOT needed (resources have no realize/2).
Instead the parameterization is:
  gate `130_example_domains.rq`  -> ?domain_module ?authorizations
  gate `140_example_resources.rq`-> ?resource_id ?domain ?data_layer
  gate `150_example_attrs.rq`    -> ?resource ?attr_name ?attr_type
                                    ?constraints ?default ?allow_nil
  gate `160_example_actions.rq`  -> ?resource ?action_name ?action_kind
                                    ?accept ?validate ?change ?atomic
  gate `170_example_extensions.rq` -> ?resource_id ?extension ?block
```

Template filters `attrs |> mine.("order")` exactly as `workflow.ex.eex`
filters `tasks` by `workflow == wname`. Camelization shared with existing
`camel` helper. Module name = `AshPPlan.Examples.QualifiedFulfillment.<Camel>`
from domain row + resource id; integration resources use
`ap:domain ex:dom_integration` with module
`AshPPlan.{ControlPlaneIntegrationDomain,ObanIntegrationDomain,
StateMachineIntegrationResource}` — handled by an optional
`ap:moduleOverride` fact so existing test references do not break
(byte-identity depends on it).

### 3.3 Template skeletons

`priv/ggen/ash-pplan-workflow-pack/templates/` (new):

`ash_domain.ex.eex`
```
---
to: "test/support/examples/qualified_fulfillment/domain.ex"
mode: file
for_each: example_domains
---
<% # same scalar/normalize/camel preamble as workflow.ex.eex %>
# GENERATED by ggen_igniter ... Regenerate with bin/manufacture-examples.
defmodule <%= module %> do
  use Ash.Domain, extensions: <%= extensions %>
  resources do
    resource <%= for r in resources_of(domain) %>...<% end %>
  end
end
```

`ash_resource.ex.eex`
```
---
to: "<%= out_path %>"
mode: file
for_each: example_resources
---
# GENERATED header (stamped, like provider.ex.eex)
defmodule <%= module %> do
  use Ash.Resource,
    domain: <%= domain_module %>,
    data_layer: Ash.DataLayer.<%= data_layer_camel %>
  <%= extension_blocks %>
  attributes do
    uuid_primary_key :id
    <%= for a <- attrs do %>
    attribute <%= inspect a.name %>, <%= a.type %>,
      <%= opts %>
    <% end %>
  end
  actions do
    defaults [:read, :destroy]
    <%= for act <- actions do %> ... <% end %>
  end
end
```

Producer wiring (bin/manufacture-examples, new sync lines):

```
sync ash_domain   ash_domain.ex.eex \
  "$OUT/qualified_fulfillment/domain.ex"            example_domains
sync ash_resource ash_resource.ex.eex \
  "$OUT/qualified_fulfillment/<%= resource_id %>.ex" example_resources
sync ash_resource ash_resource.ex.eex \
  "test/support/<%= out_path %>"           example_resource_overrides
```

### 3.4 The gate that pins the generated fixtures (byte-identity court)

New `test/courts/examples_fixture_byte_identity_court_test.exs`, cloned
from `igniter_gen_byte_identity_court_test.exs`, pointed at the new
templates:

1. determinism: render twice into run-unique
   `tmp/examples_fixture_court/run-<uniq>/` subdirs; the two outputs must
   be byte-identical (ggen_igniter refuses out-of-root --out, hence the
   in-root scratch; on_exit deletes the whole scratch root — build-root
   lease law);
2. diff-stability: render vs each committed
   `test/support/examples/qualified_fulfillment/*.ex` +
   `test/support/*_integration_resource.ex` under
   `Code.format_string!/1` normalization (same as
   `test/manufacture_test.exs`);
3. anti-vacuity: tmp-copy the pack, mutate one `ap:attrConstraints`
   fact (e.g. drop `:verified` from order status), render must diverge
   from pristine render;
4. gates-nonempty: new gates 130-170 each return >=1 row over the merged
   examples ontology; `verify/*_unbound.rq` return zero unbound vars.

Failure class -> typed receipt: `FIXTURE_DRIFT[<file>:<line>]` naming the
commit-SHA of the ontology that was supposed to have been re-pin.

## 4. Estimate

- LOC eliminated (deleted from test/support): 984 handwritten -> 0;
  replaced by ~200 LOC of ontology rows (examples.ttl grows) + ~250 LOC
  of two templates + ~150 LOC court + ~10 LOC manufacture-examples
  wiring. Net fixture-line reduction ~984; total repo LOC ~-380.
- Risk: LOW for QF resources (pure Ash DSL, no behavior). MEDIUM for
  ledger.ex (514 LOC — need to read it during R2; if it embeds real
  logic beyond attributes/actions, split it: declarative shell generated,
  logic module stays handwritten). MEDIUM for the 3 integration
  resources via the `ap:extensionBlock` free-text slot — quoted-string
  DSL blocks are the one place drift can hide; mitigated by
  anti-vacuity probe mutating the block.
- Falsifier for the whole lever: after deletion, `mix test` full suite
  green AND byte-identity court green on a clean checkout.

## 5. Phased runbook

1. **Upstream pack change**: land `ap:Example{Domain,Resource,Attribute,
   Action}` classes + SHACL shapes + gates 130-170 + templates
   `ash_domain.ex.eex`/`ash_resource.ex.eex` in the workflow pack; add
   examples.ttl rows for dom_qf + 7 QF resources; publish/commit pack.
2. **Vendor re-pin**: update `priv/ggen/vendor/PACKS.lock.json` to the
   new pack digest (pack-digest court, ggen_igniter >= 26.10.1, refuses
   stale digest); run `bin/ggen-doctor`.
3. **Regenerate**: run `bin/manufacture-examples` (MIX_ENV=test); the
   generated files land stamped `# GENERATED` over the handwritten ones;
   `mix format`; `mix test` subset touching fixtures.
4. **Byte-diff falsifier**: run the new byte-identity court; then diff
   each generated file vs the deleted handwritten one
   (`git show HEAD:<path>` vs render) — any semantic difference is either
   (a) missing ontology rows -> add rows, regenerate, or (b) genuine
   hand-logic -> keep as handwritten residual with a receipt (generated-
   vs-handwritten field).
5. **Delete handwritten**: `git rm` the 10 files only after phase 4 shows
   zero semantic diffs (or documented residuals); `mix test` full suite;
   final receipt lists the 984 LOC delta, court output, and the pack
   digest re-pinned.
