# ECO: portable-consequence-protocol-pack evaluation (ERRC G5)

Evaluated 2026-10-04. Pack: `/Users/sac/ggen-marketplace/packs/portable-consequence-protocol-pack`
(read-only). Source: read-only. No diff applied.

## 1. Target module

`lib/ash_pplan/reactor/durable/portable.ex` is the WRONG target. It is a BEAM
term-portability gate (refuses pids/ports/refs/local closures before ledger
persistence). It emits no RDF and holds no receipt/replay vocabulary. The real
consumer is `lib/ash_pplan/execution_receipt.ex`
(`AshPPlan.ExecutionReceipt`), which projects PROV-O N-Triples with `ap:`
terms.

## 2. Vocabulary overlap

Pack public fragment: PROV-O (Activity/Entity), ODRL (Permission), EARL
(Assertion), dcterms; custom remainder `urn:portable-consequence:` limited to
`admitsDigest`, `receiptCapability`, `previousReceiptDigest`, `replayKey`,
`standingCode`.

ash_pplan receipt: `ap:ExecutionReceipt` typed as `prov:Entity`, generated by
`ap:SemanticExecution` (`prov:Activity`), with `ap:runIdentifier`,
`ap:executionStatus`, `ap:resultDigest`, identity anchors `ap:repo`,
`ap:subjectSha`, `ap:baseSha` (declared in `ontology.ttl`).

Overlap: the PROV-O typing already agrees. Divergence: ash_pplan has no
authority binding (ODRL), no receipt capability pre-declaration, no replay
key, no standing code, and no chain link.

Mapping (ap -> pcp/public):

- `ap:ExecutionReceipt` (a prov:Entity) -> stays `prov:Entity`; receipt
  identity fine.
- `ap:SemanticExecution` (a prov:Activity) -> stays; pack targets receipts,
  not activities, so no change needed there.
- `ap:resultDigest` -> play the role the pack gives `pcp:admitsDigest` /
  receipt content address; keep `ap:resultDigest` but also emit the pcp
  remainder terms below.
- `ap:runIdentifier` -> candidate for `pcp:replayKey` value basis.
- No term yet for standing: pack wants `pcp:standingCode` on an `earl:Assertion`.

## 3. Minimal individual-authoring diff (NOT applied)

In `ontology.ttl`, add the pcp remainder import + three additions. Exact
triples:

```turtle
@prefix pcp: <urn:portable-consequence:> .
@prefix earl: <http://www.w3.org/ns/earl#> .

# a) standing: receipt assertions carry a pack standing code
ap:ExecutionReceipt a earl:Assertion .
ap:ExecutionReceipt pcp:standingCode
  "UNKNOWN|PARTIAL_ALIVE|ALIVE|BLOCKED|BUILD_BROKEN|UNSUPPORTED|REFUSED" .

# b) replay identity: replayKey on the receipt entity
ap:ExecutionReceipt pcp:replayKey "<runIdentifier>"^^xsd:string .

# c) authority binding: the admitting decision as ODRL Permission bound to
#    the exact consequence digest (only for anchored receipts)
[ a odrl:Permission ;
  odrl:assignee ap:SemanticExecution ;
  pcp:admitsDigest "<resultDigest>"^^xsd:string ] .
```

Runtime side (execution_receipt.ex only): one extra identity_triples entry —
`{receipt_iri, "urn:portable-consequence:replayKey",
{:literal, run_identifier(receipt.run_id)}}` — plus, when
`validate_identity/1` passes, one `pcp:standingCode` literal. Two lines.

## 4. Downstream conformance check

Once (b) and (c) exist, the pack's own gate becomes assertable:
`python3 gates/verify_protocol.py /path/to/foreign-implementation` — ash_pplan
would expose a stdin/stdout JSON operation (`verify_receipt`, `replay`)
answering the 8 vectors in `vectors/conformance.json` (e.g. `replay-identical-consequence`
-> `REPLAY_MATCH`; `refuse-replay-key-conflict` ->
`REFUSED:REPLAY_KEY_CONFLICT`). Nearer term, a SPARQL gate in the existing
ash-pplan pack (`priv/ggen/ash-pplan-*-pack/gates/`) asserting: every
`ap:ExecutionReceipt` that is `prov:wasGeneratedBy` an anchored execution
carries exactly one `pcp:replayKey` and, where `pcp:standingCode` is present,
it is in the protocol's standing enum. This is the court that would fire on
the diff.

## 5. Verdict: DECLINE (this ERRC cycle)

Falsifier: the pack's laws (`receiptability_precedes_do`,
`authority_binds_exact_consequence`) require pre-actuation authority evidence
(ODRL Permission + `pcp:admitsDigest`) that ash_pplan's receipt is
structurally defined to NOT carry — the moduledoc says "grants no actuation
authority". Conforming means adding an authority layer ash_pplan does not
have, not renaming terms. Estimated effort if adopted anyway: ~1 day
(ontology triples + 2-line projection + a stdin/stdout JSON witness for the
8-vector court) — cheap to do later; nothing is lost by declining now because
the PROV-O overlap already matches and the pack remainder is explicitly
disposable.
